# أداة استكشاف بيانات الكواكب

## المستخدم المستهدف

صُممت الأداة لفريق رصد فلكي أو طالب/باحث يريد فحص منحنيات الضوء بسرعة، مقارنة الأهداف المرصودة، ومراجعة قرار نموذج XGBoost دون الاعتماد على واجهة تجريبية أو بيانات ثابتة للعرض.

## ما الذي تقدمه؟

- **بحث وتصفية:** البحث باسم الهدف وتصفية النتائج حسب الحكم، حد الثقة، ووجود كشف عبور.
- **فهرسة الإطارات:** عرض كل الأهداف وإطاراتها من `CLEANED_DATA.csv` حتى عندما لا ينتج الاختزال قياس aperture صالحًا.
- **مقارنة:** اختيار هدفين من البيانات الموجودة وعرض الثقة وعمق العبور وSNR وعدد العينات جنبًا إلى جنب.
- **تصور:** رسم منحنى الضوء الخام والمُصحح للهدف المحدد.
- **نتيجة قابلة للتتبع:** كل نتيجة تعرض مصدر القياسات، ملف النموذج، ومرجع معلمات المقارنة.
- **تقرير:** تنزيل تقرير JSON للهدف المحدد أو للأهداف المختارة.
- **محاكاة بصرية:** الكوكب يضيء فقط عندما تكون نتيجة XGBoost `CONFIRMED PLANET`.
- **إدخال يدوي:** إدخال السمات الخمس مباشرة وتشغيل النموذج على بيانات المستخدم، مع التحقق من القيم وإظهار الثقة والتحذيرات.

## التشغيل

المتطلبات: Python 3.10+ والحزم الموجودة أصلًا في بيئة المشروع (`numpy`, `pandas`, `scipy`, `astropy`, `xgboost`). لا تستخدم الأداة Streamlit.

من مجلد المشروع:

```powershell
python standalone_exoplanet_simulator.py
```

ثم افتح:

```text
http://127.0.0.1:8765
```

## حالة استخدام كاملة

1. يقرأ الخادم `CLEANED_PHOTOMETRY.csv` ويعرض فقط الأهداف الموجودة فعليًا فيه.
2. يختار المستخدم هدفًا مثل `CoRoT-2` أو يبحث عنه في جدول الاكتشاف.
3. يشغّل التحليل، فيُطبّع المنحنى ويبحث عن العبور باستخدام BLS.
4. تُستخرج السمات الخمس المطلوبة للنموذج من المنحنى والنتيجة.
5. يُستدعى `xgb_transit_vetter.json` لإنتاج الحكم والثقة.
6. تظهر السلسلة الضوئية والكوكب وحالة الإضاءة، ويمكن تنزيل التقرير.

### إدخال بيانات المستخدم

من قسم **فحص إدخال يدوي بواسطة النموذج** أدخل:

`transit_depth`, `duration_ratio`, `snr`, `odd_even_diff`, `secondary_depth`

هذه ليست بيانات خام للكاميرا؛ إنها السمات الفيزيائية التي يتطلبها النموذج. إذا كانت البيانات لديك منحنى ضوء خامًا، يجب أولًا استخراج هذه السمات بنفس عقد التحليل قبل إدخالها.

## مصادر النتائج

- فهرس إطارات التلسكوب: `CLEANED_DATA.csv`، وعدده الحالي 1648 صفًا شاملًا إطارات المعايرة.
- القياسات الضوئية القابلة للتحليل: `CLEANED_PHOTOMETRY.csv`، ولا تُحتسب إلا الصفوف التي تحمل `is_real_data=True`.
- نموذج XGBoost: `xgb_transit_vetter.json`
- معلمات المقارنة: `NASA_BENCHMARKS` داخل `transit_detection_pipeline.py`
- طريقة التحليل: `detrend_airmass` ثم `search_bls` ثم `verify_transit`

## المنهجية والحدود

النتيجة ليست إثباتًا نهائيًا لوجود كوكب. النموذج يقيّم سمات فيزيائية مشتقة من منحنى الضوء، بينما يستخدم BLS للبحث ضمن نطاق حول الفترة المرجعية. إذا كان عدد العينات قليلًا أو التغطية الزمنية غير كافية فقد يفشل الكشف أو تصبح الثقة مضللة. بعض الإطارات قد تكون موجودة فعلًا في `CLEANED_DATA.csv` لكن لا ينتج منها aperture صالح؛ تعرضها الأداة للتتبع ولا تحوّلها إلى قياس مصطنع. كما أن ملف النموذج الحالي مدرّب على corpus اصطناعي منظم، لذلك يجب مراجعة الحكم فلكيًا وقياسه على بيانات تحقق مستقلة قبل استخدامه كقرار علمي نهائي.

## API المحلية

- `GET /api/catalog`: فهرس الأهداف ونتائجها المختصرة.
- `GET /api/analyze?target=CoRoT-2`: تحليل هدف واحد.
- `GET /api/report?target=CoRoT-2&target=TrES-5`: تقرير JSON لعدة أهداف.
- `POST /api/predict`: تنبؤ يدوي من السمات الخمس بصيغة JSON.
